仅供页面功能测试使用。
内容为演示用途，不是生产教程、也不构成任何技术建议。

这是一篇“超长 + 超复杂 + 全覆盖”的实验文。目标不是给出一套标准教程，而是把主题常见渲染能力按最容易发现问题的方式放在一篇文章里，便于你确认页面是否稳定：

  • 标题层级与自动目录
  • 混合列表（有序、无序、任务列表）
  • 多语言文本、脚注、内联代码、内联链接
  • 代码块（多语言）
  • 表格与复杂对齐
  • 公式、Mermaid、图片并排、details 折叠块
  • 外链资源与内部锚点
  • 全套短代码（quote、video、youtube、bilibili、tencent、gitlab）

10. 复杂叙事示例（长文本应力块）

在日常排版回归中，最容易出现问题的常见不是简单的短句，而是“长链条文本 + 表达式 + 列表 + 代码 + 说明文”的混合密度。比如下面这种场景：

当 markdown 渲染器遇到一个有 6 段并存的长说明块时，内部可能会因为 <p>、<pre>、<table> 的边界判断导致边距和间距出现漂移；当同段落中再叠加中文数字（如“第 1、2、3 阶段”）和英文变量（如 ctx->result、router_id）以及超链接（比如 Stack 官方演示）时，尤其容易观察出“看似正确但实际空行异常”的情况。

因此建议建立分层模板：

  1. 内容原子层（段落、列表、引用）
  2. 工具层（代码块、公式、图表）
  3. 嵌入层（图片、视频、短代码）

最终再统一在“页面快照”阶段对比：

  • 同一屏是否抖动
  • 表格是否错列
  • 图标/代码高亮是否丢失
  • mermaid 节点是否被截断
